# Спецификация языка VOLT 0.3.0

VOLT — системный, статически типизируемый язык с синтаксисом на отступах.
Компилятор написан на VOLT, кодирует инструкции x86-64 и записывает Linux ELF. Программы
по умолчанию используют системные вызовы Linux. Внешние библиотеки подключаются явно.

Здесь описано то, что реализовано в эталонном компиляторе для `linux-x86_64`
и Linux System V ABI. [Дорожная карта](../ROADMAP.md) и предложения к спецификации
не расширяют этот контракт.

## 0. Исходный текст и компилятор

**Термины:** «срез» — значение типа `[]T`; «владелец» — массив или срез,
чью память использует срез; «глобальная переменная» — переменная модуля;
«хранилище» — область памяти, где размещено значение; «привязка имени» — связь
имени с объявленным значением. В пояснениях используются русские термины,
английские написания оставлены для ключевых слов и идентификаторов языка.

- Блоки задаются отступом после `:`; используйте одинаковый отступ для
  операторов одного уровня. Фигурные скобки в `native fn` ограждают ассемблер,
  а не обычный блок VOLT. Имена чувствительны к регистру и имеют вид
  `[A-Za-z_][A-Za-z0-9_]*`.
- `#` и `//` начинают комментарий до конца строки; `/* … */` — блочный
  комментарий без вложенности. Целые литералы бывают десятичными,
  шестнадцатеричными (`0xFF`) и двоичными (`0b1010`). Для читаемости можно
  разделять цифры подчёркиваниями (`1_000`). Десятичные float-литералы имеют
  дробную часть (`1.25`) или экспоненту (`2e-3`). Без явного преобразования
  float-литерал имеет тип `f64`; целый — `i64` либо `u64`, если положительное
  значение больше максимума `i64` и умещается в `u64`.
- Строки — в двойных кавычках, `char` — в одинарных. Поддерживаются escapes
  `\n`, `\r`, `\t`, `\\`, `\"`, `\'` и `\0`; последний допустим только в `char`.
  Компилятор принимает до 8 МиБ на исходный файл и отклоняет байт NUL во входе.

```sh
make compiler                        # собрать volt из исходников VOLT
./volt prog.volt --run                # скомпилировать и запустить
./volt prog.volt -o prog              # собрать исполняемый файл
./volt prog.volt -g -o prog           # добавить привязку адресов к исходникам
./volt prog.volt --manifest volt.mod -o prog # добавить зависимости из манифеста
./volt prog.volt --emit-asm           # сохранить листинг prog.s
./volt prog.volt -S prog.s -o prog     # сохранить ELF и листинг
./volt prog.volt --parse               # вывести AST, без типизации и генерации кода
./volt --version
```

`--emit-asm` создаёт только листинг; `-S FILE` задаёт путь к нему. `--target`
принимает только `linux-x86_64`, это же цель по умолчанию. `--run` возвращает
статус запущенной программы. Без `-o` временный ELF помещается в `$TMPDIR` или
`/tmp`; при `--run` компилятор удаляет этот файл после выполнения.

При ошибке в загруженном исходнике диагностика показывает файл, строку и
ограниченный фрагмент кода. Лексер указывает байтовую колонку, когда она известна.
`-g` добавляет DWARF 4: адреса именованных функций связываются со строками их
объявлений, а тела — со строками отдельных операторов, в том числе в
импортированных модулях. Это позволяет ставить точку останова по строке и
пошагово проходить операторы командой `next` в gdb. Для исполняемого кода
верхнего уровня адрес функции запуска привязывается к первому оператору
основного файла. Описания локальных переменных и типов пока нет.
`-g` требует выходной ELF и не сочетается с `--parse` или `--emit-asm`.

## 1. Переменные и типы

```
let x: i64 = 42          # тип обязателен, если нет инициализатора
let y = 3.14             # тип выводится из инициализатора (f64)
let n: u8 = 255
const LIMIT: i64 = 100   # неизменяемая compile-time константа
```

| Тип | Размер | Описание |
|-----|--------|----------|
| `i8` `i16` `i32` `i64` | 1–8 | знаковые целые |
| `u8` `u16` `u32` `u64` | 1–8 | беззнаковые целые |
| `f32` `f64` | 4/8 | с плавающей точкой |
| `bool` | 1 | `true` / `false` |
| `char` | 1 | отдельный однобайтовый тип со значениями 0–255; литералы `'a'`, `'\n'`; при выводе `char` печатается байтом, а `u8` — десятичным числом |
| `string` | 8 | неизменяемая NUL-терминированная строка |
| `ptr<T>` | 8 | raw-указатель на `T`; операции с ним требуют `unsafe` |
| `fnptr<(A, B) -> R>` | 8 | адрес функции для скалярного C ABI (см. §4) |
| `[N]T` | N·size | массив из N элементов `T` |
| `[]T` | 16 | неизменяемый срез: указатель и длина в элементах |
| `[]mut T` | 16 | изменяемый срез с исключительным лексическим доступом |
| `struct` | зависит от полей | агрегат полей (см. §5) |
| `enum` | 8 без payload | типизированный дискриминант `i64` и необязательные данные варианта |
| `Option<T>`, `Result<T,E>` | зависит от payload | встроенные размеченные объединения (см. §5) |

Алиасы: `int` = `i64`, `uint` = `u64`, `float` = `f64`.

`const NAME[: T] = expression` объявляет неизменяемое значение. Инициализатор
должен быть константным выражением; допустимы числовые, логические, символьные
литералы, арифметика, приведения, `sizeof`/`alignof`, enum-значения и предыдущие константы. Тип
можно вывести или указать явно. Поддерживаются целые, float, `bool`, `char` и
enum без данных; `string`, указатели и агрегаты в `const` не поддерживаются. Константы
не размещаются в изменяемой памяти; присваивание им — ошибка. Объявления
допустимы в функциях и на уровне модуля.

**Явное приведение** записывается через `as`. Целочисленное приведение проверяет, что
значение помещается в целевой тип; выход за диапазон вызывает `panic`.
```
let a = 3.99 as i64        # 3 (усечение)
let b = 7 as f64 / 2.0     # 3.5
unsafe:
    let p = addr as ptr<char>
```
Смешивать `int` и `float` в арифметике без `as` нельзя. Контекст выражения
определяет допустимые неявные преобразования. Инициализация, присваивание,
аргументы функций с явными параметрами (включая `extern`/`native`) и `return`
используют одно правило числового преобразования. Сужение целых проверяется по
диапазону во время выполнения и при выходе за него вызывает `panic`. Преобразование
float в целое усекает дробную часть к нулю, но `NaN`, бесконечность и выход за
диапазон вызывают `panic`. Преобразование `f64` в `f32` следует IEEE 754 и может
дать бесконечность. Целое округляется сразу до точности целевого float (на
середине — к чётному), одинаково в константах и при выполнении. Например,
`take(1000)` для параметра `i8` вызывает `panic`, а
не передаёт `-24`; `take(3.9)` при параметре `i64` передаёт `3`, как и `return 3.9`
при результате `i64`. Generic-вызовы требуют точного совпадения выведенных типов;
встроенные функции подчиняются своим сигнатурам и ограничениям.
При смешении целых со знаком и без знака используется симметричный общий тип:
беззнаковый при одинаковой или большей ширине, иначе более широкий знаковый.
Локальный `let` без инициализатора требует явный тип; значения, допускающие
такое объявление, обнуляются. Обычный `let` допускает присваивание, в отличие
от `const` и привязки payload в `match`.

## 2. Выражения

Арифметика `+ - * /`, остаток `%` для целых, сдвиги `<< >>`, битовые
`& | ^`, сравнения `== != < <= > >=`, логика `and or not` (приоритет как в
таблице ниже). Встроенного float-оператора `%` нет.
Операнды вычисляются слева направо, в том числе в `n * string`.

`sizeof(T)` возвращает размер типа в байтах, `alignof(T)` — его выравнивание
в байтах; оба оператора вычисляются при компиляции и имеют тип `i64`. Тип записывается
внутри скобок: `sizeof(i64)`, `alignof(ptr<char>)`, `sizeof([4]u32)`. Layout
структур следует модели ABI целевой платформы x86-64: каждое поле начинается со
смещения, кратного естественному выравниванию своего типа, выравнивание структуры
равно максимальному выравниванию полей, а её размер округляется до этого значения.
Указатели и строки имеют размер и выравнивание 8 байт; `bool` — 1; массив
наследует выравнивание элемента, срез выровнен на 8 байт.

Целочисленные `+`, `-`, `*`, `/` и `%` проверяют переполнение и деление на ноль.
Переполнение вызывает `panic`, в том числе для беззнаковых типов. Для сдвигов
число сдвига должно быть в диапазоне `[0, ширина типа)`, иначе происходит `panic`.
`>>` для знакового типа — арифметический сдвиг с сохранением знакового бита;
для беззнакового — логический сдвиг с заполнением нулями. `<<` отбрасывает
вышедшие за ширину биты и не вызывает `panic` из-за потери старших битов:
например, `(64 as i8) << 1` даёт `-128`. Float-операции следуют IEEE 754 и могут
дать `inf` или `nan`; преобразование такого значения в целое вызывает `panic`.
Истинность скалярных условий и операндов `and`, `or`, `not` проверяется одинаково:
ноль и `false` ложны, ненулевое число и `true` истинны; `NaN` ложно. Операторы
`and` и `or` вычисляют правый операнд только если он нужен.

| Приоритет | Операторы |
|-----------|-----------|
| 1 (низший) | `or` |
| 2 | `and` |
| 3 | `not` |
| 4 | `== != < <= > >=` |
| 5 | `\|` |
| 6 | `^` |
| 7 | `&` |
| 8 | `<< >>` |
| 9 | `+ -` |
| 10 | `* / %` |
| 11 | унарные `- * &` |
| 12 (высший) | вызов по имени, постфиксные `.` / `[]` / `as` / `?` |

Особенности:
- `/` и `%` для целых — усечение к нулю (как в C/x86): `-7 / 2 == -3`, `-7 % 2 == -1`.
- `for i in a..b` и `for i in a..=b` принимают целочисленные границы, кроме `enum`.
  Компилятор вычисляет каждую границу один раз и проверяемо приводит её к `i64`.
  Каждое значение границы должно лежать в диапазоне
  `[-9223372036854775808, 9223372036854775807]`; выход за него вызывает `panic`
  (например, `u64` выше `i64::MAX`). Переменная цикла `i` имеет тип `i64`.
  `..` задаёт полуоткрытый диапазон `[a, b)`, а `..=` включает `b`. Диапазон
  пуст при `a > b`. При равных границах `..=` выполняет одну итерацию.
- Raw-указатели: `p + i`, `i + p` и `p - i` (шаг = размер элемента), `*p`,
  `&x`, сравнения указателей одинакового типа. Взять адрес присваиваемого
  места можно без `unsafe`; разыменование, индексация, доступ к полю через
  указатель, арифметика и raw-приведения требуют `unsafe`.
- Строки поддерживают сахар:
  `s + t` → конкатенация, `s * n` → повтор (через арену в `vstd/str.volt`).

## 3. Операторы

```
if cond:               # скалярное условие; ноль/false — ложно, ненулевое/true — истинно; NaN ложно; struct/array/Option/Result запрещены
    ...
elif other:            # сколько угодно
    ...
else:
    ...

while cond:
    ...
    break              # выход из цикла
    continue           # следующая итерация

for i in 0..10:        # i: i64, диапазон [0, 10)
    ...

for i in 1..=10:       # обе границы входят в диапазон
    ...

defer print("cleanup") # выполнить при выходе из текущего блока
return value           # значение обязательно, если указан -> тип
```

`defer statement` регистрирует один простой оператор, который выполняется при
выходе из содержащего его блока, включая обычное завершение, `return`, `break`,
`continue` и распространение ошибки через `?`. Действия выполняются в обратном
порядке регистрации (LIFO), только если управление дошло до самого объявления.
При переходе из цикла очищаются
только покидаемые области. Значение `return` сохраняется до выполнения cleanup.
Разрешён простой вызов или присваивание; условные/циклические операторы,
вложенный `defer`, объявления и управление потоком внутри действия запрещены,
включая постфиксный `?`.
Используемые локальные переменные должны быть объявлены до `defer`; выражения
читаются в момент выполнения cleanup. `panic` процессно завершает программу и
не запускает deferred actions.

Тело — блок с отступом либо один оператор на той же строке:
`if x > 0: print(x)`.
Присваивание — оператор, не выражение. Для совместимых типов доступны `=`,
`+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`.

## 4. Функции

```
fn add(a: i64, b: i64) -> i64:
    return a + b

fn hello():            # без возвращаемого значения
    print("hi")
```

- System V использует 6 целочисленных регистров (`rdi`, `rsi`, `rdx`, `rcx`,
  `r8`, `r9`) и отдельно 8 float-регистров (`xmm0`–`xmm7`). Аргументы, которым
  не хватило регистров своего класса, занимают 8-байтовые слоты на стеке в
  порядке объявления; стек выравнивается на 16 байт перед вызовом. Срез занимает
  два целочисленных регистра или целиком уходит на стек. Скрытый указатель
  результата (`sret`) занимает первый целочисленный регистр;
- функции без `->` возвращают `void`; функции с `-> T` должны вернуть значение;
- обычные VOLT-функции могут возвращать структуры; результат передаётся через
  скрытый caller-owned `sret`-указатель. Значение результата сохраняется до
  выполнения `defer`; обычные параметры-структуры передаются по значению
  через неявный указатель и копируются в слот параметра. Это внутренний ABI;
  для явного C-layout действует отдельное правило ниже;
- имя функции должно быть уникальным в своём пространстве имён; точка входа
  `main` не принимает аргументы (§7). Массивы по значению не возвращаются;
  неизменяемый срез можно вернуть с явно указанным параметром-источником (§6).

Записывайте параметры объявления на одной строке. Аргументы передаются
позиционно; именованные аргументы, значения по умолчанию, вложенные функции и
перегрузка функций не поддерживаются.

### Колбэки C

Внешняя функция объявляется, например, как
`unsafe extern fn puts(text: ptr<char>) -> i32` и связывается с разделяемой
ELF-библиотекой через `link "-lc"`. Фиксированную сигнатуру и время жизни данных
должен проверить вызывающий. Кроме небольших `extern struct` в прямых
`extern fn`, агрегаты передаются через указатель на хранилище вызывающего.
Массивы, срезы, `Option`/`Result` и enum с payload не пересекают C ABI по значению.

`fnptr<(A, B) -> R>` описывает адрес функции для C. Для `void` используйте
`fnptr<(A, B)>`. Выражение `callback(имя_функции)` в `unsafe` возвращает
такой адрес. Компилятор сравнивает параметры и результат с сигнатурой получателя.

```volt
link "-lc"
unsafe extern fn qsort(base: ptr<i32>, n: u64, size: u64, cmp: fnptr<(ptr<char>, ptr<char>) -> i32>)

unsafe fn compare(a: ptr<char>, b: ptr<char>) -> i32:
    let left: i32 = *(a as ptr<i32>)
    let right: i32 = *(b as ptr<i32>)
    if left < right: return -1
    if left > right: return 1
    return 0

let values: [3]i32 = [5, 3, 4]
unsafe: qsort(&values[0], 3 as u64, 4 as u64, callback(compare))
print(values[0], values[1], values[2]) # 3 4 5
```

Адрес относится к обычной именованной функции VOLT. Поддерживаются целые,
числа с плавающей точкой, `bool` и raw-указатели, в том числе на стеке.
VOLT `enum` передаётся как `i64`; это не представление перечисления C.

### Структуры по значению в C ABI

```volt
link "-lc"
extern struct DivResult:
    quot: i32
    rem: i32
unsafe extern fn div(numerator: i32, denominator: i32) -> DivResult

unsafe:
    let result = div(17, 5)
    print(result.quot, result.rem) # 3 2
```

`extern struct` использует естественные смещения и выравнивание Linux x86-64
System V. Допустимы целые, `char`, `bool`, raw-указатели, `f32` и `f64`; размер
структуры — до 16 байт. Обычные VOLT-функции используют внутренний ABI даже для
этих типов. Поддержаны только прямые `extern fn` с фиксированным числом
аргументов. Вложенные, упакованные и обобщённые C-структуры, вариативные вызовы,
`native` и колбэки со структурами по значению не поддерживаются.

### Непрямой вызов `fnptr`

В `unsafe` локальную переменную или параметр типа `fnptr` можно вызвать как
`f(args)`. Компилятор проверяет арность и типы, а параметры передаёт по тому же
System V ABI, что и при прямом вызове. Сначала считывается адрес, затем слева
направо вычисляются аргументы. Нулевой адрес завершает программу с диагностикой
`volt: null fnptr call` до вычисления аргументов. Имена обычных функций,
конструкторов и встроенных операций сохраняют приоритет.
Вызов без результата (`void`) нельзя использовать как условие.

Явное `raw as fnptr<...>` требует `unsafe`. Внешний адрес, его сигнатуру и срок
жизни библиотеки проверяет вызывающий. Вызов поля или произвольного выражения
не поддерживается: сначала сохраните адрес в локальной переменной.

```volt
fn increment(value: i64) -> i64:
    return value + 1

unsafe:
    let f = callback(increment)
    print(f(41)) # 42
```

### Generic-функции (ограниченная первая версия)

Функции могут объявлять параметры типа и компилируются отдельным экземпляром для
каждой выведенной комбинации типов:

```volt
fn identity<T>(value: T) -> T:
    return value

print(identity(42), identity(true))
```

Параметры типа выводятся из аргументов вызова, включая вложенные обобщённые
структуры и указатели. Если одному параметру соответствуют разные типы,
компилятор сообщает о конфликте. Указатели в сигнатурах специализаций требуют
`unsafe fn`. Для вызова применяется обычный ABI VOLT. Массивы передаются через
срезы или указатели. Обобщённые функции используют вывод типов при вызове и
доступны в обычном коде VOLT.

#### Ограничение `T: Eq`

У параметра типа функции можно указать единственное встроенное ограничение
`T: Eq`. Оно допускает знаковые и беззнаковые целые (`i8`…`i64`, `u8`…`u64`,
включая алиасы `int` и `uint`), `char`, `string` и `enum` без данных. Для них
применяется обычное `==`/`!=`: строки сравниваются по содержимому, значения
перечисления — по дискриминанту в пределах одного типа. `bool`, массивы, срезы,
структуры, `Option`/`Result` и `fnptr` не удовлетворяют `Eq`. Типы `f32`/`f64`
и raw-указатели тоже не удовлетворяют `Eq`, хотя у них есть обычное `==`.

```volt
fn contains<T: Eq>(values: []T, needle: T) -> bool:
    for i in 0..len(values):
        if values[i] == needle:
            return true
    return false

let ints = [2, 4, 6]
let words = ["volt", "core"]
print(contains(ints[0..3], 4), contains(words[0..2], "core")) # true true
```

Если `contains` объявлена в импортированном модуле, а ей передать срез структур
`Record` и значение `Record`, диагностика укажет на строку вызова в импортирующем
файле, например:

```text
main.volt:5: ошибка: contains: ограничение T: Eq не выполнено для Record
```

Для вызова через обобщённые функции ошибка указывает на исходный вызов, который
запустил специализацию. Проверка выполняется при компиляции; способ вызова
функций и ABI не меняются.

### Raw asm (native fn)

Для низкоуровневого кода есть `native fn`. Компилятор создаёт пролог и эпилог,
передаёт параметры по System V ABI и кодирует инструкции Intel x86-64 из тела
функции. В теле первый стековый слот доступен по `[rbp+16]` после пролога.
Неизвестные инструкции и формы операндов вызывают ошибку компиляции.

```
native fn raw_add(a: i64, b: i64) -> i64:
{
    mov rax, rdi
    add rax, rsi
}
```

Тело не должно содержать `ret` — эпилог (`mov rsp, rbp; pop rbp; ret`)
добавляет реализация; `native fn` автоматически считается unsafe и вызывается
только из `unsafe:`-контекста.

## 5. Структуры

```
struct Point:
    x: f64
    y: f64

let p = Point(1.5, 2.5)     # конструктор
print(p.x)                   # доступ к полю
let q: ptr<Point> = &p
unsafe:
    q.y = 0.0                # доступ через raw-указатель
let r = p                    # копия (побайтовое)
```

Поля выравниваются по естественному выравниванию; вложенные структуры и
вложенные конструкторы (`Outer('Q', Inner(7, 8))`) поддерживаются.

### Обобщённые структуры

```volt
struct Item<T>:
    index: i64
    value: T

fn item_value<T>(item: Item<T>) -> T:
    return item.value

let item: Item<u32> = Item(0, 42)
let inferred = Item(1, true)
print(item_value(item), item_value(inferred), sizeof(Item<u32>))
```

Конструктор использует тип места назначения, если он задан. В остальных
случаях компилятор выводит параметры из полей. Каждая специализация имеет свой
размер и выравнивание. Параметры могут использоваться во вложенных структурах,
массивах и указателях. Рекурсивная ссылка допустима через `ptr<T>`.

### Перечисления

```volt
enum Block:
    Air
    Dirt = 4
    Stone

let block: Block = Block.Stone
if block == Block.Stone:
    print(block as i64) # 5
```

Варианты без явного значения получают предыдущий дискриминант + 1, начиная с
нуля. Значения имеют тип `i64`; разные enum-типы нельзя смешивать или сравнивать.
Допустимы только `==`/`!=`; явное `as i64` позволяет получить числовой
дискриминант. Это представление enum без данных не изменилось. Вариант может
также хранить одно скалярное значение: `Number(i64)`, `Name(string)`.
Такой enum передаётся только в VOLT, не сравнивается через `==` и не приводится
к целому. См. [примеры enum с payload](enum-payloads.md).

### `match`, `Option<T>` и `Result<T, E>`

`match` — оператор, а не выражение: каждая ветка выполняет блок операторов и
не возвращает значения. Сопоставление поддерживает enum (с данными и без них),
`Option<T>` и `Result<T, E>`.

```volt
enum Color:
    Red
    Green
    Blue

let color = Color.Green
match color:
    Color.Red:
        print("red")
    Color.Green:
        print("green")
    Color.Blue:
        print("blue")

let maybe: Option<i64> = Some(42)
match maybe:
    Some(value):
        print(value)
    None:
        print("empty")

let result: Result<i64, i32> = Ok(7)
match result:
    Ok(value):
        print(value)
    Err(code):
        print(code)
```

Грамматика (все разделители и блоки подчиняются обычным правилам отступов):

```text
match expression:
    pattern:
        statements
    ...

pattern := _ | EnumName.Variant | EnumName.Variant(identifier) | None | Some(identifier)
         | Ok(identifier) | Err(identifier)
```

`_` покрывает все ещё не покрытые варианты. `match` должен иметь хотя бы один arm
и быть исчерпывающим: без `_` каждый вариант входного enum/суммы должен встретиться
ровно один раз; `_` завершает покрытие. Повторное покрытие `_` или уже покрытого
варианта — ошибка дубликата, в том числе arm после `_`. Несовместимый с типом
scrutinee образец — ошибка типа. Порядок arms — порядок выбора, но образцы не могут
перекрываться, поэтому затенение не меняет поведение. `match` над числами, `bool`,
строками, структурами, массивами или указателями не поддерживается.

В ветке `Some(name)`, `Ok(name)`, `Err(name)` или `Token.Number(name)` переменная
видна только в этой ветке. Обычно она получает копию payload. У
[`Result<OwnedBuffer, E>` и `Option<OwnedBuffer>`](owned-buffer.md) `match`
потребляет обёртку, а `Ok(name)`/`Some(name)` переносят буфер в переменную
ветки. Привязки по ссылке не поддерживаются.
Вариант без данных пишется без привязки. Значение для сопоставления вычисляется
ровно один раз.

`Option<T>` и `Result<T, E>` — встроенные параметризованные типы с фиксированным
набором вариантов и собственными правилами для payload и `?`.

`T` и `E` допускают скаляры, enum, разрешённые `ptr<U>`, копируемые `struct` и
копируемые вложенные `Option`/`Result`. Непосредственно хранить массив, срез или
`BorrowBuffer` нельзя. Владеющий struct из реестра (`OwnedBuffer`, `fs.OwnedFd`)
допустим только как payload `Ok` у прямого
[`Result<OwnedBuffer, E>`](owned-buffer.md) с копируемой ошибкой или как payload
`Some` у прямого `Option<OwnedBuffer>`; вложение владеющих обёрток друг в друга
запрещено. Указатели на
размеченные значения запрещены. См. также [пример `Result<FileInfo, IoError>`](option-result-payloads.md).
В записи `Option<T>` или `Result<T, E>` аргумент типа задаётся в
аннотации; в конструкторе локального `let` он выводится из фактического payload
или окружающего контекста. Аргументы типов точны:
неявное числовое преобразование payload при конструировании, сопоставлении или
propagation не выполняется. Имена `Option`, `Result`, `Some`, `None`, `Ok`, `Err`
зарезервированы для встроенных типов/вариантов и не могут объявляться как
пользовательские типы или функции.

Выражения-конструкторы: `Some(value)` создаёт `Option<T>`, `None` — пустой
`Option<T>`, `Ok(value)` создаёт `Result<T, E>`, `Err(error)` — ошибку
`Result<T, E>`. Payload у `Some`/`Ok`/`Err` должен иметь в точности объявленный
тип; обычные числовые widening/narrowing conversions здесь не применяются.
При объявлении локального `let` с типом-целью контекст полного результата
передаётся конструктору. Локальный `let` с явной аннотацией поддерживает
`Some`, `None`, `Ok` и `Err`; payload должен точно соответствовать типу.
`match` wrapper разрешён над локальной переменной или результатом функции,
но не над непосредственным `Some`/`None`/`Ok`/`Err`.
Wrapper нельзя хранить в глобальных переменных/константах, полях структур
или элементах массивов; автоматическое zero-init wrapper также запрещено.
Корневые `let` во входном файле являются локальными объявлениями синтетической
функции `__voltmain__`, поэтому там можно хранить и сопоставлять wrapper-значения.
Повторное присваивание разрешено для копируемых локальных значений и параметров
обычной VOLT-функции. Типы слева и справа должны совпадать в точности. Правая часть
вычисляется один раз до записи, в том числе при присваивании самому себе. При
копировании сохраняются метка и активный payload, неиспользуемые байты обнуляются.

Постфиксный оператор `?` применяется к значению `Option<T>` или
`Result<T, E>` внутри обычной VOLT-функции с совместимым wrapper-результатом.
Это реализованное поведение. Регрессионные и golden-тесты запускаются из корня
репозитория командами `python3 tests/regressions.py` и `python3 tests/run.py`.

```volt
fn maybe_double(input: Option<i64>) -> Option<i64>:
    let value = input?
    return Some(value * 2)

fn checked(input: Result<i64, i32>) -> Result<i64, i32>:
    return Ok(input? + 1)
```

На успешном пути `?` копирует payload `Some`/`Ok`, а для `Result<OwnedBuffer, E>`
и `Option<OwnedBuffer>` потребляет обёртку и переносит буфер. На пути ошибки
функция сразу возвращает `None` или `Err(error)`; владеющая обёртка
потребляется и на пути `None`/`Err`.
Для `Option` тип параметра и результата должен совпадать. Для `Result` тип
ошибки должен совпадать точно; success-типы могут различаться, так как `?`
переносит только ошибку, а payload успешного варианта разворачивается в значение
выражения. Несовместимый контекст, применение к не-wrapper значению и невыводимый
тип конструктора — семантические ошибки с указанием файла и строки.

Propagation использует обычный путь `return`: результат сохраняется до
выполнения зарегистрированных `defer` в LIFO-порядке и автоматических `drop`,
затем сохранённый результат копируется в caller-owned `sret`. Оператор
разрешён во вложенных выражениях, например в аргументах функций или payload
конструктора. Wrapper ABI и `?` поддерживаются только обычными VOLT-функциями;
wrapper-типы запрещены в `extern`/`native` ABI и не образуют совместимость с C ABI.

Типы представлены встроенным размеченным объединением без выделения памяти
в куче. `Option<T>` хранит метку `i64` (0 = `None`, 1 = `Some`) и область
размера `sizeof(T)`, выравнивания `alignof(T)`. У `Result<T,E>` метка `i64`
имеет значения 0 = `Ok`, 1 = `Err`; размер и выравнивание области payload —
максимумы по `T` и `E`. Если `P` — размер области payload, `A` — её выравнивание,
то смещение payload равно `align_up(8, A)`, выравнивание всего значения —
`max(8, A)`, а размер — `align_up(align_up(8, A) + P, max(8, A))`. Здесь
`align_up` обозначает округление к кратному, а не функцию языка. `None` имеет
нулевую область payload. `sizeof` и `alignof` учитывают всё размещение.

ABI wrappers определён только для обычных VOLT-функций: параметры передаются
неявным указателем на значение и копируются в локальные слоты; результат
передаётся через `sret`. Снимок результата создаётся до `defer`, затем копируется
в хранилище вызывающего кода с выровненным стеком. Перенос байтов не зависит от
значения флага направления DF. Неявный указатель параметра передаётся как
целочисленный аргумент, включая стек при исчерпании регистров. Это не C ABI.

Диагностика должна указывать файл и строку и различать как минимум: не-исчерпывающий
`match` (с непокрытыми вариантами), повторный/перекрывающийся шаблон, неизвестный
или неподходящий вариант, повторное имя привязки, невозможность вывести полный
тип `None`/`Ok`/`Err`, несовместимый тип payload, неподдерживаемый `?`, применение
wrapper в сигнатуре функции или в запрещённом контексте хранения. Для enum,
участвующего в `match`, значения-дискриминанты
должны быть уникальны: повторное явное/неявное числовое значение — ошибка
объявления, иначе runtime tag не позволил бы отличить варианты. Совпадающее имя
варианта в разных enum допустимо, как и сейчас: pattern всегда квалифицирован
именем enum.

Не поддерживаются: `match` как выражение, guards, destructuring структур/массивов,
явные привязки по ссылке или с `move`, неявное преобразование payload/error,
C FFI wrappers, heap boxing, `null`-значения и преобразования между `Option` и `Result`.

## 6. Массивы и указатели

### Срезы: реализованное подмножество

Неизменяемый срез `[]T` создаётся через `values[start..end]`, изменяемый
`[]mut T` — через `mut values[start..end]`. Срез занимает 16 байт (указатель и
длина). Индексация и вычисление границ проверяются в рантайме. Оба вида среза
можно передавать обычным VOLT-функциям.
Например:

```volt
fn sum(values: []i64) -> i64:
    let total = 0
    for i in 0..len(values):
        total += values[i]
    return total

let data: [4]i64 = [10, 20, 30, 40]
let middle: []i64 = data[1..3]
let alias = middle
print(sum(alias)) # 50
```

`let alias = view` копирует только указатель и длину уже объявленного
локального среза или параметра `[]T`, не копируя элементы. Алиас не может
пережить исходный срез и не продлевает и не снимает его заимствование.

Пока есть хотя бы один `[]T`, исходный массив доступен только для чтения.
Пока есть `[]mut T`, читать и менять массив разрешено только через этот срез.
Из `[]mut T` можно создать дочерний срез `[]T` диапазона — `buf[0..n]` без
`mut`; пока дочерний срез жив (до конца его блока), запись через исходный
`[]mut T` и передача его как `[]mut` запрещены, чтение разрешено.
Заимствование всего массива действует до конца блока, включая `defer`; оно не
зависит от пересечения диапазонов. После
выхода из блока запись снова разрешена, если нет внешнего заимствования.
Временный срез, переданный прямо в вызов, заимствует массив только до конца
оператора с этим вызовом: если вызов не возвращает заимствование (нет
`-> []T from input`), доступ к массиву разрешён уже со следующего оператора;
внутри самого оператора конфликты проверяются по-прежнему.
Функция с `-> []T from input` может вернуть поддиапазон своего неизменяемого
параметра `input`, но не срез локального массива. Источником `from` может быть
и адрес владельца: `owned_buffer_bytes(&buffer) -> []u8 from buffer` отдаёт
байты `OwnedBuffer` без копирования, пока срез жив, буфер нельзя перенести
(см. [owned-buffer.md](owned-buffer.md)). `[]mut T` нельзя копировать
или возвращать. Срезы нельзя переприсваивать, хранить в агрегатах или передавать
через C ABI. См. [правила и примеры](slice-borrows.md).
Анализа до последнего использования и проверки raw-указателей нет. Код `unsafe`
сам отвечает за то, чтобы не нарушать время жизни и неизменяемость заимствования.
Предложение и полный целевой контракт — в
[`slices-proposal.md`](slices-proposal.md).

```
let v: [4]i64 = [1, 2, 3, 4]   # инициализация списком
let z: [10]i64                  # нулевой массив
let copy: [4]i64 = v            # копирование массива того же типа
print(v[2], len(v))             # индексация, число элементов
v[0] += 10
let p: ptr<i64> = &v[0]
unsafe:
    print(*(p + 2))
```

Локальные массивы живут на стеке. В `[N]T` длина `N` задаётся целочисленным
литералом, а не параметром generic. У `let data = [10, 20, 30]` длина выводится
из списка, тип — из первого элемента. Пустой список сам по себе тип не задаёт.
Лишние элементы инициализатора — ошибка, недостающие обнуляются. Копирование
требует того же типа массива. Элементами
массива могут быть и структуры: `[Point(1, 2), Point(3, 4)]`, а конструктор
структуры разрешён в присваивании по любому lvalue (`pts[1] = Point(3, 4)`,
`s.inner = Point(0, 0)`), не только в `let`. Индексация массива
известной длины проверяется во время выполнения: отрицательный индекс и индекс
`>= N` завершают программу с сообщением `array index out of bounds`. Индексация
через `ptr<T>` не проверяет границы и разрешена только в `unsafe`-коде.

### Растущий буфер `Buffer<T>`

```volt
use buffer

struct Node:
    parent: i64
    tag: i64

fn main() -> i64:
    unsafe:
        let nodes: Buffer<Node>
        defer buffer_free(&nodes)
        if buffer_push(&nodes, Node(-1, 1)) < 0: return 1
        let first: ptr<Node> = buffer_at(&nodes, 0)
        print(buffer_len(&nodes), first.tag)
    return 0
```

Нулевое значение буфера пустое. `buffer_reserve` принимает вместимость в
элементах и сохраняет их при росте. Тип элемента должен иметь положительный
размер. `buffer_capacity` и `buffer_len` возвращают число элементов.
`buffer_push` добавляет значение, а `buffer_at` проверяет индекс и возвращает
указатель. `buffer_data` даёт прямой доступ к выделенной памяти.
`buffer_reserve`, `buffer_push` и `buffer_free` возвращают 0 либо отрицательный errno.

Буфером владеет один экземпляр. Передавайте его по указателю и освобождайте
через `buffer_free`. Указатели на элементы получайте заново после роста буфера.

`ByteBuffer` из [`bytes`](../vstd/bytes.volt) хранит `data`, длину и ёмкость в
байтах, включая NUL, и поддерживает чтение произвольного файла. Инициализируйте
новый буфер нулевым значением или `bytes_init`, проверяйте статусы операций и
освобождайте его с `bytes_free`. Правила единственного владельца и срока жизни
указателей те же, что у `Buffer<T>`.

### Типизированный буфер с лексическим чтением

[`use borrow_buffer`](buffer-borrow-proposal.md) добавляет `BorrowBuffer<T>` и
представление `BufferRead<T>`. Копии владельца ссылаются на одну запись реестра.
`let view = borrow_buffer_read(owner)` открывает чтение до выхода из блока,
включая выход через `return`, `break`, `continue` или `?`. Представление нельзя
скопировать, сохранить или вернуть. Чтение элемента возвращает поверхностную
копию, не указатель на хранилище. Пока есть читатель, запись, рост и освобождение
через любую копию владельца возвращают `-16` (`EBUSY`). Освобождение самого
владельца остаётся явным. Обычные `Buffer<T>` и `ByteBuffer` не меняются.

### Арена для временных объектов

[`use arena`](arena.md) выделяет одну область фиксированной ёмкости. В ней
создаются выровненные объекты без отдельного освобождения и без перемещения
предыдущих объектов. Сброс позволяет использовать область повторно, а закрытие
освобождает её целиком. Оба действия делают все ранее выданные указатели
недействительными. Время жизни и синхронизацию обеспечивает вызывающий в `unsafe`.

### Безопасный байтовый буфер `ByteVec`

```volt
use bytevec

fn main() -> i64:
    let bytes: ByteVec = byte_vec_new()
    if byte_vec_len(bytes) < 0: return 1
    defer byte_vec_drop(bytes)
    if byte_vec_push(bytes, 0) < 0 or byte_vec_push(bytes, 255) < 0: return 1
    let tail: ByteView = byte_vec_view(bytes, 1, 2)
    match byte_view_get(tail, 0):
        Ok(value): print(value)
        Err(error): return 1
    return 0
```

`ByteVec` хранит байты, включая NUL, и растёт в куче. `ByteView` — проверяемый
диапазон `[start, end)` с собственной длиной. Он не держит указатель на данные:
рост буфера не меняет диапазон, а изменение байта через `byte_vec_set` видно
в представлении. `byte_vec_get` и `byte_view_get` возвращают `Result<u8, i32>`
с `Err(34)` для неверного индекса/диапазона и `Err(9)` для закрытого или
недействительного дескриптора. `byte_vec_len`, `byte_view_len`, `byte_vec_push`,
`byte_vec_set` и `byte_vec_drop` сообщают об ошибке отрицательным errno.

Освобождение явное: ставьте `defer byte_vec_drop(bytes)` сразу после создания.
Копия `ByteVec` указывает на тот же буфер; `drop` делает недействительными все
его копии и представления, даже если место в реестре занял новый буфер. Реестр
вмещает 64 буфера на процесс; при исчерпании `byte_vec_new()` возвращает
недействительный дескриптор (`byte_vec_len` вернёт `-9`). Это не общий механизм
владения для `Buffer<T>`, не граница доступа между модулями и не замена
встроенному срезу `[]T`.

### Строки

`string` — отдельный неизменяемый тип NUL-терминированной строки. Индексация
считает байты UTF-8 и проверяет границы; индекс за длиной вызывает `panic`.
Встроенный NUL (`\0`) запрещён в строковых литералах: он завершил бы строку
раньше последующих байтов. Для хранения нулевого байта используйте массив `char`.
Сравнение `==`/`!=` сравнивает содержимое. Чтобы передать строку в C API, явно
преобразуйте её в `ptr<char>` внутри `unsafe:`-блока.
Проверка индекса `string` каждый раз пересчитывает длину до NUL. Для разбора
текста без копирования используйте [`text_view.TextView`](text-view.md):
длина, индексация и поддиапазоны за O(1), явное копирование в C-строку.

```volt
let name: string = "VOLT"
print(name[0], name == "VOLT", str_len(name))
```

### Владение ресурсами

[`OwnedBuffer`](owned-buffer.md) — некопируемый владелец байтового буфера.
Он переносится через `let`, вызов, `return`, `Ok` в `Result<OwnedBuffer, E>` и
`Some` в `Option<OwnedBuffer>`; использование после возможного переноса —
ошибка. При выходе из блока `defer` выполняются до автоматического
освобождения живых владельцев, в том числе нераспакованного `Ok`/`Some`.
`panic` и `exit` не запускают очистку.

## 7. Модули

Файл подключается словом `use`. Компилятор ищет `NAME.volt` рядом с импортирующим
файлом, затем по порядку в `vstd/`, `browser/modules/`, `gpu/modules/` и
`tools/modules/` относительно корня установки. Имена модулей от путей не зависят:
```
use math
use fs, process
```

- верхнеуровневые `const` — неизменяемые compile-time константы без изменяемого
  хранилища; `let` в модуле — глобальные переменные с константным инициализатором;
- верхнеуровневые вызовы функций — инициализация модуля, выполняется до `main`;
- зависимости инициализируются раньше импортирующего модуля, каждый файл — один
  раз; цикл импорта — ошибка;
- файлы без заголовка `module` сохраняют прежний плоский `use`;
- `module NAME` задаёт пространство имён файла. `use NAME [as ALIAS]` даёт
  доступ к экспорту как `NAME.member` или `ALIAS.member`. `pub` экспортирует
  функции, структуры, перечисления и константы. У `pub struct` виден тип,
  но конструктор и поля доступны только внутри файла модуля. Импорты не
  переэкспортируются. См. [пример и правила миграции](modules.md);
- `link "-lm"` подключает разделяемую библиотеку. Компилятор находит
  `libNAME.so` по `-lNAME` или точное имя файла по `-l:FILE`. `-LPATH`
  дополняет пути поиска на этапе компиляции. При запуске библиотеку ищет
  системный загрузчик Linux;
- [`volt.mod`](volt-mod.md), переданный через `--manifest`, может добавлять
  библиотеки и каталоги для выходного ELF. Он не меняет поиск `use`, ничего не
  скачивает и не запускает скрипты;
- модули `io` и `str` подключаются автоматически.

После инициализации модулей выполняются верхнеуровневые операторы входного
файла, затем `main`, если она объявлена в этом файле. Здесь верхнеуровневый
`let` — локальная переменная сгенерированной точки входа, а не глобальная
переменная модуля. Используйте `fn main() -> i64` для статуса процесса или
`fn main():` без результата. Параметров у `main` нет: аргументы можно прочитать
через `use process`. Если значение статуса не возвращается, код выхода равен 0.

## 8. Стандартная библиотека

**Всегда доступны (intrinsics):**
`sin cos tan log2 atan2 sqrt` (float), `abs min max` (числовые типы), `len`
для массивов и срезов, `sizeof` и `alignof` для типов. `panic(message)` пишет
диагностику в stderr и завершает процесс ненулевым статусом; `exit(status)`
завершает процесс с заданным статусом. Они не раскручивают стек.

Низкоуровневые `read`, `write`, `write_all`, `open`, `close`, `mmap`, `munmap`
и `brk` работают с контрактом системных вызовов Linux. Для интерфейсов с raw-данными
вызывающий отвечает за действительность адресов, длины, время жизни и проверку
возвращаемого статуса. Эти функции не создают безопасные ссылочные типы.

**`io` (авто):** `print(...)` — вывод значений через пробел + `\n`;
знаковые и беззнаковые числа печатаются десятично, значения типа `char` — одним байтом как символ,
`f32`/`f64` — с шестью знаками после точки; большие значения float выводятся
в научной записи. Ошибка записи вызывает `panic`, а не теряется. Также доступны
`put_char put_str put_int put_uint put_float put_bool put_err put_errnl nl`.

**`str` (авто):** `str_len str_eq str_concat str_repeat`, сахар `s + t`, `s * n`.
Операции работают с неизменяемым `string`. Динамические результаты конкатенации
и повтора выделяются в общей арене 1 МиБ на процесс с безусловным завершением
при её исчерпании; резервирование памяти синхронизировано между потоками.
Это не предел для всех байтовых буферов.

**`math` (через `use math`):** `PI E TAU`, `powi ipowi fact gcd floor ceil
round clamp sign hypot iabs log10 ln exp`.
`powi` и `ipowi` используют возведение в степень за `O(log |n|)` и корректно
обрабатывают `INT64_MIN`; для `ipowi` отрицательная степень даёт целую часть
обратного значения (`ipowi(2, -2) == 0`, `ipowi(-1, -3) == -1`). Переполнение
`fact`, `ipowi` и остальных целочисленных операций вызывает `panic`.

**`time` (через `use time`):** `monotonic_ms() -> Result<i64, i32>` возвращает
монотонное время с начала загрузки системы в миллисекундах либо положительный
Linux `errno`. Часы подходят для измерения интервалов, но не для получения даты
или календарного времени. Реализация использует `clock_gettime(CLOCK_MONOTONIC)`
через syscall и поддерживается только на Linux x86-64.

**`fs` (через `use fs`):** `file_size(path) -> Result<i64, i32>` возвращает
логический размер объекта по пути в байтах либо положительный Linux `errno`.
Размер получается через `statx`, поэтому для sparse-файлов возвращается их
логический размер, а результат отражает состояние пути на момент вызова.
`create_dir(path, mode)` создаёт один каталог (биты прав `0x000..0x1ff`, с учётом
umask или ACL). `rename_path(old, new)` атомарно переносит запись без перезаписи
существующего назначения; если ядро или файловая система не поддерживают этот
режим, возвращается ошибка. `remove_file(path)` удаляет файл или саму конечную
символьную ссылку; `remove_dir(path)` удаляет только пустой каталог. Все четыре
операции возвращают `Ok(0)` или `Err` с положительным `errno`. Пути передаются как
NUL-терминированные `string` и разрешаются по правилам Linux, без изоляции пути.
`fs.read_all(path, max_bytes)` читает обычный файл целиком, но не более
`max_bytes` байт, и возвращает некопируемый `Result<OwnedBuffer, fs.IoError>`:
`Err(EINVAL)` при `max_bytes <= 0`, `Err(EFBIG)` при превышении лимита,
`Err(EISDIR)` для каталога и `Err(ESPIPE)` для FIFO, сокета или устройства
(открытие с `O_NONBLOCK` и `fstat` по открытому дескриптору не блокируются на
FIFO без писателя и не имеют гонки stat→open), иначе положительный `errno`
ядра; пустой файл и файл ровно `max_bytes` байт валидны, а буфер никогда не
освобождается вручную. `fs.read_into(&handle, dst)` читает из `fs.OwnedFd`
в срез `[]mut u8`, а `fs.close_owned(handle)` явно закрывает дескриптор,
потребляя владельца ровно один раз.

**`process` (через `use process`):** `argc() -> i64` возвращает число
аргументов процесса, а `arg_at(index: i64) -> Result<string, i32>` возвращает
аргумент по индексу. Для отрицательного или выходящего за границы индекса
возвращается `Err(22)`. Аргументы берутся из начального Linux x86-64 process
stack; возвращённая строка действительна на время работы процесса и не является
копией.

**`event` (через `use event`):** `poll(fds: []mut EventPollFd, timeout_ms: i64) -> Result<i64, i32>`
возвращает число готовых записей. Ядро заполняет `revents` в переданном диапазоне.
Вызов не требует `unsafe`: передайте `mut entries[start..end]` или переменную
с таким срезом. Читайте `revents` через срез, пока он жив, или через массив
после окончания заимствования. Пустой срез передаётся как `NULL` с `nfds == 0`.
`poll_readable(fd: i64, timeout_ms: i64) -> Result<i64, i32>` по-прежнему возвращает
маску `revents` одного дескриптора, а не число записей.
`timeout_ms == -1` означает бесконечное ожидание, `0` — немедленную проверку;
для `poll` `Ok(0)` означает тайм-аут, а успешный ненулевой результат содержит число
готовых записей; в их `revents` находятся маски
`POLLIN`, `POLLOUT`, `POLLPRI`, `POLLERR`, `POLLHUP` и `POLLNVAL`. Обе функции
возвращают `Err(22)` при тайм-ауте вне диапазона `-1..=INT32_MAX`; `poll_readable`
также проверяет, что `fd` находится в `0..=INT32_MAX`. Ошибки системного вызова
возвращаются как положительный Linux `errno`.
Модуль также предоставляет unsafe timerfd API: `timer_create() -> Result<i64, i32>`
создаёт неблокирующий `CLOCK_MONOTONIC`-дескриптор с `TFD_CLOEXEC`,
`timer_set(fd, first_ms, interval_ms) -> Result<i64, i32>` устанавливает
относительный таймер, а `first_ms == 0` его выключает. Оба значения должны быть
неотрицательными и не превышать `9223372036854775`; `interval_ms == 0` означает
одноразовое срабатывание. `timer_read(fd) -> Result<u64, i32>` считывает ровно
счётчик истекших периодов из timerfd; для созданного неблокирующего дескриптора
до срабатывания или после потребления счётчика возвращается `Err(11)` (`EAGAIN`).
`timer_close(fd) -> Result<i64, i32>` закрывает дескриптор. Timerfd содержит
`POLLIN` при наличии истечений и передаётся в `poll` как обычный дескриптор.

`unsafe stream_pair(&pair)` записывает в `EventStreamPair` два конца локального
двунаправленного Unix-сокета с `NONBLOCK` и `CLOEXEC`. При ошибке `pair` не меняется;
при успехе каждый конец нужно закрыть через `event_close`. `try_read(fd, buffer: []mut u8)`
и `try_write(fd, buffer: []u8)` выполняют одну неблокирующую операцию над подключённым
потоковым сокетом без `unsafe`: длина берётся из среза, а пустой срез отклоняется
с `Err(22)` (`EINVAL`), поэтому `Ok(0)` при чтении всегда означает конец потока,
а не пустой буфер. Возможны частичный результат и `Err(11)` (`EAGAIN`, повтор после
готовности `POLLIN`/`POLLOUT`). Запись закрытому соседу может вернуть `EPIPE` без
`SIGPIPE`. Формы с сырым указателем и длиной сохранены как `unsafe try_read_raw` и
`unsafe try_write_raw`.
Модуль работает без libc на Linux x86-64. Это примитивы готовности, не `async/await`
и не асинхронные операции с файлами.

**[`thread`](../vstd/thread.volt) (через `use thread`):** опциональные pthread на
Linux x86-64 с glibc ≥ 2.34. `unsafe thread_spawn` запускает типизированный колбэк
`(ptr<char>) -> ptr<char>`, `unsafe thread_join` ждёт его завершения и возвращает
указатель или код ошибки pthread. Слот `Thread` должен быть обнулён перед первым
запуском, не перемещаться и не копироваться до успешного `join`; все указатели
на данные потока должны оставаться действительными до `join`. `Mutex` и
`Condition` требуют явной инициализации, уничтожения и стабильного адреса.
`mutex_try_lock` не ждёт освобождения, `condition_timed_wait` принимает абсолютное
монотонное время в миллисекундах и возвращает захваченный мьютекс при успехе или
таймауте. Проверяйте условие ожидания в цикле. Вызывающий отвечает за синхронизацию
и освобождение ресурсов; [контракт pthread-обёрток](thread.md) описывает ограничения.

**[`channel`](channel.md):** копируемый дескриптор `ChannelI64` передаёт одно
значение `i64` за раз. Можно ждать отправку и получение или использовать
варианты `try_*`. Операции сами синхронизируют очередь и не выдают ссылок на её
память. Нельзя отправить указатель или структуру. Это гарантия для сообщений
канала, не автоматическая проверка произвольных потоков или их данных.

## 9. Границы реализации

- Поддерживаются Linux x86-64 и ограниченный System V ABI. Сборка чистого VOLT
  не требует C/C++, Python, внешнего ассемблера или линковщика. Необязательные
  библиотеки и воркеры браузера имеют собственные зависимости.
- `unsafe` — явная граница ответственности, а не песочница: raw-указатели и FFI
  не проверяют время жизни, границы и соответствие внешней сигнатуре. Проверка
  заимствований срезов лексическая, а автоматический `drop` есть только у
  `OwnedBuffer`, в том числе внутри `Result` и `Option`; владение обычными
  `Buffer<T>` остаётся ручным.
- Нет traits, замыканий, const generics, кортежей, макросов, `async`/`await`
  языка VOLT и сборщика мусора. `native fn`
  не означает поддержку произвольных inline-asm-блоков. JavaScript-воркеры
  браузера и CUDA — отдельные интеграции, не возможности синтаксиса VOLT.

[`tests/run_all.py`](../tests/run_all.py) запускает golden-тесты и проверки ABI,
срезов, диагностики, системных модулей и браузера. Проверка двух поколений
самосборки: `make verify-bootstrap`. Предложения о новых возможностях —
в [дорожной карте](../ROADMAP.md).
