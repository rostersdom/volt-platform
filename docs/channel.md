# Каналы `i64` в VOLT

`use channel` предоставляет канал с одним ожидающим значением `i64`.
Операции канала не требуют `unsafe`: библиотека копирует значение под мьютексом,
а тип сообщения не может содержать указатель или ссылку на изменяемый объект.
Создание потока через `use thread` по-прежнему `unsafe`: время жизни пользовательского
контекста и синхронизацию остальных данных обеспечивает вызывающий.

```volt
use channel

fn main() -> i64:
    let messages = channel_i64_new()
    defer channel_i64_drop(messages)
    if channel_i64_send(messages, 42) != 0: return 1
    if channel_i64_close(messages) != 0: return 1
    match channel_i64_recv(messages):
        Ok(value): print(value)
        Err(error): return 1
    return 0
```

- `channel_i64_new()` возвращает копируемый `ChannelI64`. Нулевой дескриптор
  означает, что нет свободных слотов. Копии обращаются к одной очереди.
- `channel_i64_send` ждёт свободного места, а `channel_i64_recv` — значения.
  Ожидание идёт через условную переменную, без активного опроса. Закрытие и
  освобождение будят ожидающих; при освобождении они получают `EBADF`.
- `channel_i64_try_send(handle, value)` возвращает `0`, либо `EAGAIN` (11) для
  занятого слота, либо `EPIPE` (32) для закрытого канала.
- `channel_i64_try_recv(handle)` возвращает `Ok(value)`, либо `Err(EAGAIN)`
  для пустого открытого канала, либо `Err(EPIPE)` для пустого закрытого.
- `channel_i64_close(handle)` идемпотентно запрещает отправку, сохраняя
  ожидающее значение. `channel_i64_drop(handle)` освобождает слот, отбрасывает
  ожидающее значение и делает все копии дескриптора недействительными.
- Недействительные дескрипторы дают `EBADF` (9). При повторном выделении
  слот получает новое поколение; старая копия не обращается к новой очереди.

До 64 живых каналов на процесс; между процессами они не работают. Варианты `try`
берут мьютекс, но не ждут данных или места. Блокирующие операции не имеют
дедлайна и могут ждать бесконечно, если другой участник не продолжит работу
или не закроет канал.
Порядок между ожидающими потоками не гарантируется. Дескриптор не является
границей доступа между модулями. Канал не передаёт указатели, строки или
структуры; универсального `Send`/`Sync` пока нет.

Модуль опирается на pthread из glibc 2.34+ на Linux x86-64. Без `use channel`
или `use thread` зависимости от pthread для программы не добавляются.
Не вызывайте операции канала из обработчика сигнала или в дочернем процессе
между `fork` многопоточной программы и `exec`.
В [интеграционном примере](../tests/fixtures/vstd_channel.volt) четыре потока
передают значения одному получателю. `unsafe` нужен на границе запуска и
передачи контекста pthread, а не при отправке или получении сообщений.
