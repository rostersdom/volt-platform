# Потоки в VOLT

Опциональный `use thread` подключает pthread из `libc.so.6` для Linux x86-64
LP64 с glibc 2.34+. VOLT сохраняет собственный `_start`; программы без этого
импорта не получают от него динамической зависимости.

## Владение и синхронизация

`Thread`, `Mutex` и `Condition` — ресурсы вызывающего кода. Начните с нулевых
слотов (`let task: Thread`, `let lock: Mutex`, `let ready: Condition`) и держите
их по стабильным адресам. Не копируйте, не перемещайте и не меняйте поля
живого слота. Инициализируйте `Mutex` и `Condition` до публикации их адресов.
Освобождение явное; перед выходом сделайте `thread_join` для каждого успешно
запущенного потока. Слот `Thread` использует только запустивший его поток.
`thread_spawn` может запустить `callback` до возврата: сохраняйте данные
живыми до успешного `thread_join` и синхронизируйте общий доступ. `thread_join`
возвращает `Result<ptr<char>, i32>`; `Ok` может содержать `NULL`. Не отдавайте
указатель на стек рабочего потока. Время жизни памяти аргумента и результата
остаётся ответственностью вызывающего.

Мьютекс обычный, нерекурсивный, для одного процесса. `mutex_lock` блокируется,
а `mutex_try_lock(ptr<Mutex>) -> i32` возвращает `0` при захвате или
`THREAD_EBUSY` (`16`), если мьютекс уже занят, в том числе текущим потоком.
Вызвать `mutex_unlock` может только владелец. `mutex_destroy` допустим лишь
для незахваченного мьютекса, когда никто им не пользуется, не ждёт его (в том
числе через ожидание `Condition`) и не может начать новую операцию с ним.

## Условная переменная

Все функции `unsafe` и возвращают `i32`: `0` при успехе, иначе номер ошибки,
не `errno` и не отрицательное значение.

| Функция | Аргументы | Действие |
| --- | --- | --- |
| `condition_init` | `ptr<Condition>` | Инициализирует пустой слот. |
| `condition_wait` | `ptr<Condition>, ptr<Mutex>` | Отпускает захваченный мьютекс атомарно с началом ожидания и захватывает снова перед успешным возвратом. |
| `condition_timed_wait` | `ptr<Condition>, ptr<Mutex>, i64` | То же с абсолютным дедлайном `CLOCK_MONOTONIC` в миллисекундах. При истечении возвращает `THREAD_ETIMEDOUT` (`110`), также с захваченным мьютексом. |
| `condition_signal` | `ptr<Condition>` | Будит хотя бы одного ожидающего, если он есть. |
| `condition_broadcast` | `ptr<Condition>` | Будит всех ожидающих. |
| `condition_destroy` | `ptr<Condition>` | Освобождает ресурс, оставляя слот пригодным для повторного `condition_init`. |

Перед ожиданием захватите мьютекс. Все одновременно ожидающие на одной
`Condition` используют тот же `Mutex`. Читайте и меняйте предикат под этим
мьютексом. Сигнал не сохраняется для будущих ожидающих; пробуждение может
оказаться ложным или предикат успеет измениться до захвата мьютекса. Поэтому
вызывайте wait в цикле, повторно проверяя предикат под мьютексом.

Для `condition_timed_wait` берите время из `monotonic_ms()` (`use time`) и
передавайте один и тот же дедлайн при каждом повторе ожидания. Дедлайн в
прошлом тоже приводит к попытке отпустить и заново захватить мьютекс.
Событие может совпасть с таймаутом: прежде чем обработать таймаут, проверьте
предикат под захваченным мьютексом. Дедлайн ограничивает ожидание события,
но не время повторного захвата мьютекса.

NULL, использование пустого слота, повторный init и копия живого слота по
другому адресу отклоняются с `THREAD_EINVAL` (`22`) до вызова pthread.
Отрицательный дедлайн также даёт `THREAD_EINVAL`. Эти проверки не отпускают
мьютекс. Ошибки из pthread возвращаются без преобразования. Ошибка init
оставляет слот неинициализированным, ошибка destroy — инициализированным.
После успешного destroy можно снова вызвать init без обнуления слота.

Уничтожайте `Condition` только после возврата всех вызовов
wait/signal/broadcast и исключив новые вызовы. Destroy не будит ожидающих;
нельзя полагаться на него как на проверку отсутствия пользователей.

Посмотрите локальный [пример очереди](../tests/fixtures/vstd_thread_queue.volt)
с одним производителем и несколькими потребителями. Это примитивы `unsafe`,
не механизм проверки `Send`/`Sync`, владения произвольными указателями или
гонок. Невалидные указатели, нарушения предусловий и ручные операции pthread
над этими ресурсами не защищены. Отмена потоков, lock-free операции и перенос
на Windows не поддерживаются.
