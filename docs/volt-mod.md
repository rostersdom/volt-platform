# `volt.mod`: зависимости от C-библиотек

Манифест хранит параметры линковки отдельно от исходников. Компилятор читает его
только по явному флагу, поэтому соседний `volt.mod` не меняет сборку сам по себе.

```text
# volt.mod
library = m
```

```volt
# main.volt
unsafe extern fn modf(value: f64, integer_part: ptr<f64>) -> f64

let integer_part: f64
unsafe:
    let fraction = modf(3.5, &integer_part)
    print(integer_part, fraction) # 3.000000 0.500000
```

```sh
./volt main.volt --manifest volt.mod --run
```

- `library = NAME` ищет `libNAME.so`, как `link "-lNAME"`. Начальный `:`
  задаёт точное имя файла. Библиотеки должны быть разделяемыми ELF для Linux x86-64.
- `library-dir = PATH` добавляет каталог поиска при сборке. Относительный путь
  считается от каталога пути, переданного в `--manifest`, не от места запуска.
  Символические ссылки в пути разрешает ОС. Внутренние пробелы
  буквальные; кавычки и подстановки переменных не обрабатываются.
- Допустимы пустые строки и комментарии, начинающиеся с `#` после отступа.
  Синтаксис — одна запись `ключ = значение` на строку, не TOML. Лимиты —
  64 КиБ и 64 записи. Неизвестные ключи и недопустимые имена — ошибки.

Для уже собранной локальной библиотеки, например `vendor/lib/libexample.so.1`,
добавьте `library-dir = vendor/lib` и `library = :libexample.so.1`.

Прежние `link`-директивы и порядок поиска модулей `use` сохраняются. Для
линковки сначала учитываются имена и каталоги из исходников, затем из
манифеста, затем стандартные системные каталоги. Дубли имён не добавляют
повторную зависимость. Сигнатуру `extern fn` по-прежнему нужно объявить в VOLT.

Манифест не скачивает пакеты, не запускает shell или внешний линковщик и не
добавляет пути поиска при запуске. Для локальной `.so` системному загрузчику
может понадобиться системная установка или явно заданный `LD_LIBRARY_PATH`.
Используйте доверенные библиотеки: это обычный C FFI, не песочница. Флаг
`--manifest` применяется к выходному ELF, не к `--parse` или `--emit-asm`.
