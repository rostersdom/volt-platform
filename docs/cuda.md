# CUDA в VOLT

`use cuda` подключает небольшой набор функций NVIDIA CUDA Driver API для Linux
x86-64 (System V ABI, glibc 2.34+). Компилятор не использует CUDA Toolkit,
заголовки NVIDIA, `nvcc` или `-lcuda`. Программы без `use cuda` не получают
новых зависимостей. Программа с `use cuda` линкуется с системной `libc`, а
`libcuda.so.1` открывается через `dlopen` только при вызове `cuda_open`.

## Пример на GPU

Из корня проекта:

```bash
out=$(mktemp -d "${TMPDIR:-/tmp}/volt-cuda.XXXXXX")
./volt apps/cuda_smoke.volt -o "$out/cuda-smoke"
CUDA_CACHE_DISABLE=1 "$out/cuda-smoke"
```

Пример показывает число доступных устройств и имя устройства с индексом 0,
создаёт контекст, выделяет четыре байта памяти на GPU и копирует туда `19`.
Драйвер JIT-компилирует встроенный PTX 6.0 (`sm_50`). Один поток прибавляет
переданное ему `23`. После синхронизации программа читает результат из памяти
GPU, проверяет `42` и освобождает модуль, память, контекст и дескриптор библиотеки.
Ожидаемая последняя строка: `CUDA PTX smoke passed: 19 + 23 = 42`.

Код выхода `77` означает, что библиотеку драйвера не удалось открыть или нет
видимого CUDA-устройства. Другие ошибки возвращают `1`; диагностика показывает
операцию и код ошибки. Для примера нужен драйвер с рабочим PTX JIT и совместимым
GPU. VOLT не генерирует PTX из функций языка.

## Использование API

Все функции `unsafe` и возвращают код `i64` (`0` — успех), кроме
`cuda_error_name`, которая возвращает строку. Положительные коды — `CUresult`,
отрицательные — ошибки загрузчика VOLT: `CUDA_DRIVER_UNAVAILABLE` (`-1`, не
удалось открыть библиотеку), `CUDA_DRIVER_INCOMPATIBLE` (`-2`, нет нужного
символа) и `CUDA_DRIVER_CLOSE_FAILED` (`-3`, сбой `dlclose`). `CUDA_ERROR_NO_DEVICE`
(`100`) может вернуть сам драйвер; успешный `cuda_device_count` также может дать
нулевое число устройств. Выходные параметры действительны только при успехе.

| Функции | Что делают |
| --- | --- |
| `cuda_open(&driver)`, `cuda_close(&driver)` | Открывают библиотеку и вызывают `cuInit(0)`; закрывают библиотеку после освобождения GPU-ресурсов. Закрытие уже закрытого экземпляра ничего не делает. |
| `cuda_device_count`, `cuda_device_get`, `cuda_device_name` | Получают число, дескриптор (`i32`) и имя устройства. Для имени передайте записываемый буфер и его размер в байтах. |
| `cuda_context_create`, `cuda_context_destroy`, `cuda_synchronize` | Создают и разрушают непрозрачный контекст; ждут завершения команд в текущем контексте. |
| `cuda_alloc`, `cuda_free`, `cuda_copy_to_device`, `cuda_copy_to_host` | Управляют памятью устройства и копируют байты. Адрес устройства и размер (`size_t`) — `u64`; адрес устройства нельзя разыменовывать как хост-указатель. Размер выделения и копирования должен быть ненулевым. |
| `cuda_module_load_ptx`, `cuda_module_function`, `cuda_module_unload` | Загружают NUL-терминированный PTX, находят функцию по имени, выгружают модуль. |
| `cuda_launch_1d(driver, kernel, blocks, threads, args)` | Асинхронный запуск: `u32`-размеры сетки и блока по X, по Y/Z — 1, динамическая shared memory — 0, стандартный legacy stream. `args` — указатель на массив хост-указателей **на значения** аргументов ядра (`NULL`, если аргументов нет). |
| `cuda_error_name(driver, status)` | Описывает служебные коды и запрашивает имя `CUresult` у открытого драйвера. Строку, полученную от драйвера, используйте только до `cuda_close`. |

Объявите нулевой `let driver: CudaDriver`, передавайте его по адресу и не
копируйте открытый экземпляр. Не изменяйте его поля. Создание контекста делает его
текущим на вызывающем потоке. Выполняйте все операции и очистку в этом потоке,
с одним текущим контекстом. Регистрируйте `defer` сразу после успешного получения
ресурса. Перед освобождением ресурсов, которые использует запущенное ядро,
дождитесь его завершения через `cuda_synchronize`. Размер и время жизни
хост-буферов, ABI-типы аргументов и валидность непрозрачных дескрипторов —
ответственность вызывающего.
Модуль не управляет потоками CUDA, переключением контекстов или автоматическим
владением ресурсами.

Для контекста и памяти берутся нужные экспортируемые символы `_v2`. Нативные
переходники вызывают указатели `dlsym` по System V ABI; для `cuLaunchKernel`
пять последних целочисленных аргументов передаются через стек. Официальные
справки NVIDIA: [контекст CUDA 12.4](https://docs.nvidia.com/cuda/archive/12.4.1/cuda-driver-api/group__CUDA__CTX.html),
[память](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__MEM.html),
[модули](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__MODULE.html),
[запуск ядра](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__EXEC.html),
[PTX](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html).

## Тесты

```bash
TMPDIR="$out" python3 tests/cuda_integration.py -v
TMPDIR="$out" VOLT_CUDA_GPU=1 python3 tests/cuda_integration.py -v
CUDA_VISIBLE_DEVICES= CUDA_CACHE_DISABLE=1 "$out/cuda-smoke" # код выхода 77
readelf -d "$out/cuda-smoke" # DT_NEEDED: libc.so.6, без libcuda
```

Тесты без GPU моделируют отсутствие `libcuda`, неполную библиотеку, отсутствие
устройств, ширину адреса устройства, передачу аргументов запуска и порядок
очистки на успехе и ошибках. Для сборки тестовой заглушки нужен обычный `cc`, не
`nvcc`. `VOLT_CUDA_GPU=1` дополнительно требует реальный успешный запуск PTX;
ошибки драйвера и отсутствие GPU в этом режиме не считаются успехом.
