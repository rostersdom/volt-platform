# Arena в VOLT

`use arena` даёт линейный аллокатор для группы временных объектов. Под Linux
x86-64 каждая арена владеет одной анонимной RW-областью `mmap`, без libc.
Она не растёт и не переносит выделенные блоки. Рабочая ёмкость — ровно
заданное число байтов, даже если ядро округлило размер области до страницы.
Промежутки для выравнивания расходуют эту ёмкость.

```volt
unsafe fn arena_init(slot: ptr<Arena>, capacity: i64) -> i64
unsafe fn arena_alloc(slot: ptr<Arena>, size: i64, alignment: i64) -> Result<ptr<u8>, i64>
unsafe fn arena_reset(slot: ptr<Arena>) -> i64
unsafe fn arena_drop(slot: ptr<Arena>) -> i64
```

- `arena_init` принимает нулевой слот (`let slot: Arena`) и положительную
  ёмкость. Повторный `init` активного слота — ошибка.
- `arena_alloc` требует положительный размер в байтах и положительную степень
  двойки для выравнивания. Возвращает `Ok(ptr)` на непересекающийся блок.
  Адреса не меняются до `reset` или `drop`; освобождения отдельных блоков нет.
- `arena_reset` делает все ранее выданные указатели недействительными, но
  сохраняет отображение и возвращает позицию к началу. Байты не очищаются.
- `arena_drop` снимает отображение; при успехе указатели истекают, а слот снова
  нулевой и годится для `init`. `reset`, `alloc` и `drop` пустого слота — ошибки.
  Ни `reset`, ни `drop` не закрывают ресурсы объектов и не вызывают деструкторы.

Успешные `init`, `reset`, `drop` возвращают `0`. Ошибки — отрицательные коды
Linux, для `alloc` внутри `Err`. Ошибка вызова не меняет слот или позицию.

| Код | Причина |
| --- | --- |
| `ARENA_EINVAL` (`-22`) | Нулевой указатель на слот, неподходящее состояние слота, неверный размер или выравнивание |
| `ARENA_ENOSPC` (`-28`) | Блок с учётом выравнивания не помещается, в том числе для заведомо огромного запроса |
| `ARENA_EOVERFLOW` (`-75`) | Полученное отображение нельзя представить как ненулевой диапазон адресов в `i64` |
| Отрицательный `errno` ядра | Ошибка `mmap` или `munmap`, например `-12` (`ENOMEM`) |

Храните активный `Arena` по одному адресу от `init` до успешного `drop`.
Не копируйте, не перемещайте и не перезаписывайте слот, не меняйте его поля
и не управляйте отображением напрямую. Проверка собственного адреса отклоняет
копию по другому адресу, но не отслеживает восстановленные снимки, поддельные
слоты и висячие указатели. В `unsafe`-коде вызывающий отвечает за валидный слот,
инициализацию байтов до чтения, границы, типы и время жизни указателей. Арена
не контролирует алиасы, не синхронизирует потоки и не привязывает raw-указатели
к слоту или фазе работы. Для размера массива проверяйте умножение **до** вызова.

## Пример

```volt
use arena

struct ScratchPoint:
    x: i64
    y: i64

fn main() -> i64:
    unsafe:
        let scratch: Arena
        if arena_init(&scratch, 4096) != 0: return 1
        let result = arena_alloc(&scratch, sizeof(ScratchPoint), alignof(ScratchPoint))
        let code: i64 = 1
        match result:
            Ok(raw):
                let point = raw as ptr<ScratchPoint>
                point.x = 3
                point.y = 4
                print(point.x, point.y)
                if arena_reset(&scratch) == 0: code = 0
            Err(status):
                print("arena_alloc:", status)
        if arena_drop(&scratch) != 0: return 1
        return code
```

Проверка из корня проекта: `make compiler` и `python3 tests/vstd_arena.py`.
