# `OwnedFd`: файловый дескриптор с автоматическим закрытием

`use fs` даёт второй владеющий тип VOLT: некопируемый `fs.OwnedFd`,
единственный владелец файлового дескриптора Linux. Компилятор больше не
привязан к `OwnedBuffer`: реестр владеющих типов (`cc_owner_kinds` в
`compiler/volt_ownership.volt`) сопоставляет каждому владельцу домашний файл,
reader-функции и функцию drop. Для `OwnedFd` drop — это
`__volt_owned_fd_close`, которая вызывает `close(2)` и намеренно игнорирует
ошибку закрытия.

`fs.open_owned(string)` открывает файл только для чтения и возвращает
`Result<fs.OwnedFd, fs.IoError>`; прямой вызов конструктора `fs.OwnedFd(...)`
закрыт модульной приватностью. Перенос происходит при инициализации другого
`let`, передаче в обычную VOLT-функцию по значению, `return`, извлечении через
`match` и `?`. После переноса исходное имя недоступно, а попытка скопировать
владельца — ошибка компиляции.

```volt
use fs

fn first_descriptor(path: string) -> Result<i64, fs.IoError>:
    let handle = fs.open_owned(path)?
    defer print("closing")
    return Ok(fs.owned_fd_number(&handle)) # close(2) — после defer, ровно один раз
```

`fs.owned_fd_number(&handle)` возвращает номер живого дескриптора, ничего не
перенося. Адрес нельзя сохранить или передать другой функции; отложенное
чтение через `defer` заимствует владельца до конца блока и запрещает перенос.

Порядок очистки общий с [`OwnedBuffer`](owned-buffer.md): сначала `defer`
блока в обратном порядке, затем ещё живые владельцы в обратном порядке
инициализации слотов — на обычном выходе, `return`, `?`, `break` и `continue`.
Повторного закрытия не бывает: перенос гасит флаг живости исходного слота,
поэтому номер, уже переиспользованный ядром для другого дескриптора, не
закрывается дважды. `panic` и `exit` стек не раскручивают.

`Result<fs.OwnedFd, E>` с копируемым `E` и `Option<fs.OwnedFd>` работают по
той же схеме, что [`Result<OwnedBuffer, E>` и `Option<OwnedBuffer>`](owned-buffer.md):
вся обёртка некопируемая, `Ok`/`Some` переносят дескриптор, `match` и `?`
потребляют обёртку, живой `Ok`/`Some` закрывается после `defer` ветки или
области, включая отброшенный в `_`, а `None` ничего не закрывает.

Ограничения общие для владеющих типов: без частичного переноса,
переприсваивания, хранения в структурах, массивах и срезах, без
`OwnedFd` в `Err`, вложенных владеющих обёрток, пользовательского `drop` и
C ABI. Копируемый `fs.Descriptor` и ручной `fs.close_file` не меняются и
остаются `unsafe`-отмеченной альтернативой.
