# Лексическое чтение типизированного буфера

**Статус:** реализован узкий MVP в `use borrow_buffer`. Нужны компилятор из
`compiler/volt_main.volt` и стандартная библиотека из той же сборки. Сборка
модуля компилятором без этих проверок отклоняется.
Существующие `Buffer<T>`, `ByteBuffer`, `ByteVec`, `ByteView` и `[]T` не меняются.

```volt
use borrow_buffer

fn main() -> i64:
    let initial: [2]i64 = [12, 30]
    let values = borrow_buffer_new(initial[0..2])
    if borrow_buffer_len(values) < 0: return 1
    defer borrow_buffer_drop(values)
    let alias = values
    if true:
        let first = borrow_buffer_read(values)
        let second = borrow_buffer_read(alias)
        print(buffer_read_len(first), buffer_read_get(second, 0)) # 2 12
        print(borrow_buffer_push(alias, 7)) # -16 (EBUSY), без записи
    return -borrow_buffer_push(values, 7) # 0: оба чтения завершились
```

`borrow_buffer_new(slice)` копирует значения в новый буфер и выводит `T` из
`[]T`. Для пустого буфера передайте пустой диапазон типизированного массива.
При ошибке создания возвращается нулевой дескриптор. `BorrowBuffer<T>` копируем:
копии обозначают одну запись реестра. Успешный `borrow_buffer_drop` делает все
копии недействительными; повторное использование слота меняет поколение.
При исчерпании счётчика поколений слот не используется вновь. Освобождение
владельца явное. Конструктор и поля дескриптора доступны только реализации
стандартного модуля; типизированные преобразования через raw-указатель
не дают переинтерпретировать владельца, в том числе внутри generic-структур.
Проверка консервативна: она учитывает `BorrowBuffer<T>` и в аргументах типа,
которые структура не использует в полях.

- **Компилятор** принимает `let view = borrow_buffer_read(owner)` без аннотации
  типа, где `owner` — имя дескриптора. При получении представления регистрируется
  скрытый `defer`, который завершает это заимствование ровно один раз при выходе
  из блока: обычном, `return`, `break`, `continue` или через `?`. Захватывается
  значение дескриптора, не переменная владельца. `BufferRead<T>` нельзя создать
  вручную, скопировать, переназначить, сохранить, вернуть или передать
  пользовательской функции. Имя представления разрешено только в `buffer_read_len`
  и `buffer_read_get`; последняя возвращает **копию значения**, не адрес.
  Заимствование не завершается по последнему употреблению. Последующие `defer`
  того же блока могут читать представление; более ранний
  `defer borrow_buffer_drop(owner)` выполнится после скрытой очистки по LIFO.
  Оператор `?` разрешён в теле блока, но не в самом действии `defer`.
  `panic` и завершение процесса не исполняют `defer`.
- **Рантайм** под одной блокировкой проверяет поколение и считает читателей общей
  записи. Пока есть хотя бы один читатель, `borrow_buffer_reserve`,
  `borrow_buffer_push`, `borrow_buffer_set` и `borrow_buffer_drop` возвращают
  `-16` без изменений, в том числе при вызове через другую копию или функцию.
  Чтение длины и другие читатели разрешены. Нулевой или устаревший дескриптор
  даёт `-9` в операциях владельца; заимствование такого дескриптора и чтение за
  границей вызывают `panic`. Неверный индекс записи даёт `-34`, отрицательное
  резервирование — `-22`, переполнение размера — `-75`.

Реестр на 64 записи на процесс (Linux x86-64) использует общую блокировку. Для
полного API нужен `T` ненулевого размера, который обычные безопасные VOLT-функции
могут принять и вернуть по значению (например, число или структура; не массив
верхнего уровня и не raw-указатель). Это не общий borrow checker: нет изменяемых
представлений, диапазонов представления, автоматического `drop` владельца или
гарантий для raw-доступа через `unsafe` и FFI.

Копирование элемента поверхностное. Если `T` содержит указатель или другой
дескриптор, заимствование защищает запись самого элемента, но не объект, на
который он ссылается. В частности, оно не продлевает жизнь объекта в арене после
её `reset`/`drop`: безопасный API арены должен проверять действительность ссылки
при доступе или не выдавать ссылки, которые переживут сброс. Raw-адреса после
сброса использовать нельзя; их время жизни остаётся обязанностью `unsafe` кода.

## Почему не `Buffer<T>` или `ByteView`

Копия `Buffer<T>` или `ByteBuffer` сохраняет адрес той же аллокации, но копирует
длину и ёмкость. Блокировка локального имени не защищает память от `reserve`,
`free` или записи через другой экземпляр или уже полученный raw-указатель.
`ByteView` использует смещения и проверяет поколение, но намеренно разрешает
владельцу рост, запись и освобождение. Это проверяемое представление, не заём.
Новый API не принимает и не выдаёт raw-буфер; ABI обычных функций и срезов не
расширяется. Покрытие: `python3 tests/compiler_buffer_borrow.py` после `make compiler`.
