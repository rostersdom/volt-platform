# Онлайн-режим браузера VOLT

Браузер VOLT — не обёртка вокруг Chromium, WebKit или WebView. HTML, CSS,
раскладку, отрисовку и сетевую политику реализует код проекта; внешние
библиотеки дают только транспортные примитивы и системные вызовы. Этот документ
описывает онлайн-часть: адресную строку, загрузку HTTP(S) и сеть для сценариев.

## Адресная строка и веб-поиск

Адресная строка различает три вида ввода:

- `http://` и `https://` — прямой переход;
- локальный или относительный путь (`/`, `./`, `../`, имя с `/`) — файл;
- всё остальное, включая текст с пробелами и одиночное слово, — веб-поиск.

Провайдер задаётся префиксом в `VOLT_SEARCH_URL`, например
`https://search.example/?q=`. Префикс обязан начинаться с `http://` или
`https://`, не содержать пробелов и `#`; иначе используется встроенный
`https://html.duckduckgo.com/html/?q=`. Запрос кодируется как
`application/x-www-form-urlencoded`: пробел становится `+`, всё вне
`A-Z a-z 0-9 - . _ ~` — `%XX` от UTF-8. Ссылки и история хранят уже готовый
URL, поэтому повторный поиск не выполняется.

`--search QUERY` проходит тот же путь без окна и удобен для проверок:

```sh
VOLT_SEARCH_URL='http://127.0.0.1:8080/?q=' \
  apps/bin/browser --check --search 'hello world'
```

## Транспорт

`vstd/http.volt` и `vstd/tls.volt` реализуют собственный ограниченный клиент:

- HTTP/1.0, GET и POST с `Content-Length`, один запрос на соединение;
- разбор ответа HTTP/1.0 и HTTP/1.1, `Content-Length` и `Transfer-Encoding:
  chunked`, `identity` и одиночный `gzip`;
- DNS через libc `getaddrinfo` (IPv4), TLS через OpenSSL 3 с проверкой цепочки
  и имени хоста;
- абсолютный монотонный дедлайн на DNS, соединение, запись и чтение;
- лимиты запроса 8 КиБ, ответа — настраиваемые; для страниц 2 МиБ HTML и
  64 КиБ заголовков.

Это не Chrome-подобный стек: нет пула соединений, HTTP/2, кэша, cookie-jar,
приоритетов, предварительного соединения, прокси и фоновых спекулятивных
загрузок. Такие возможности не заявлены. Один переход — один ограниченный
запрос; отмена и дедлайн проверяются на каждом шаге.

## Сеть для JavaScript

Воркер `--js` изолирован фильтром системных вызовов и не умеет открывать
сокеты. `fetch` и `XMLHttpRequest` работают через брокер:

1. Воркер отправляет браузеру кадр с методом, URL, `Content-Type` и телом.
2. Браузер разрешает URL относительно документа и требует тот же origin:
   совпадают схема, хост и порт. Абсолютный чужой URL и перенаправление за
   пределы origin отклоняются до соединения.
3. Браузер выполняет запрос своим транспортом (HTTP или HTTPS) и возвращает
   статус, тело и `Content-Type`; ответ ограничен 256 КиБ, перенаправлений не
   больше трёх.
4. Воркер получает ответ и разрешает промис.

Запрос синхронный по отношению к воркеру: его стек ждёт ответа. Страница
остаётся простой и детерминированной, но обработчик клика с `fetch` может
задержать кадр до 3 с. Это осознанное ограничение первой версии, а не
event-loop уровня Chrome. `fetch` поддерживает `text()`, `json()`, `ok`,
`status`, `url` и `headers['content-type']`; `XMLHttpRequest` —
синхронные `open`/`send`, `status`, `responseText`, `getResponseHeader` и
`onload`/`onreadystatechange`. HTTP-статусы, включая `404`, разрешают промис;
сетевые ошибки и нарушение origin — отклоняют.

CSP с `connect-src` пока не разбирается: страницы с любым поддерживаемым CSP
не запускают сценарии, поэтому сетевой брокер для них недоступен.

## Проверки

- `python3 tests/browser_search_bar.py` — распознавание URL, кодирование
  запроса и переопределение провайдера.
- `python3 tests/browser_javascript.py` — GET, POST, JSON, 404, XHR,
  same-origin и отказ при чужом origin/перенаправлении.
- `python3 tests/browser_https.py` — проверенный TLS для документов; HTTPS
  для `fetch` использует тот же TLS-модуль.
