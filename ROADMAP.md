# Дорожная карта VOLT

Текущая версия языка — **0.3.0**; reference toolchain ориентирован на Linux x86-64.
Отметки описывают существующую реализацию; незакрытые пункты — планы, а не
заявленная поддержка.

## 0.1.0 — VOLT Core (готово)

- [x] Статические целые и float-типы, функции, структуры и управление потоком
- [x] Массивы фиксированной длины, указатели и компиляция в x86-64 ELF
- [x] Файловые модули через `use`, базовые `io`, `str` и `math`

## 0.2.0 — VOLT System (готово)

- [x] `f32`/`f64`, payload-free `enum` и проверки типов enum
- [x] Runtime-проверки границ для массивов фиксированной длины
- [x] `mmap`/`munmap` и динамический байтовый `ByteBuffer`
- [x] Чтение произвольных бинарных файлов через `bytes`
- [x] `Vec2`, `Vec3`, `Mat4` и базовые операции в `math3d`
- [x] Начальный C FFI (`unsafe extern fn`, `link`) с диагностикой ограничений ABI

## 0.3.0 — VOLT Safe Core (текущая версия)

- [x] Иммутабельный тип `string` с проверкой границ индексации
- [x] Проверка переполнения целой арифметики и числовых преобразований
- [x] Явные `unsafe:`-блоки и `unsafe fn` для raw-указателей, FFI и syscalls
- [x] Обработка ошибок записи стандартной библиотекой
- [x] Регрессионный набор и повторяемый benchmark для массивов/арифметики
- [x] Минимальный bounded HTTP/1.0 GET для IPv4/TCP на Linux x86-64 (`use http`)
- [x] Проверка готовности одного или нескольких дескрипторов через `use event`
      и Linux x86-64 `poll`; `poll_readable(fd, timeout_ms)` возвращает маску
      одного дескриптора, а `poll(fds, timeout_ms)` принимает `[]mut EventPollFd`,
      заполняет `revents` и возвращает число готовых записей или errno;
      timerfd API предоставляет монотонные относительные таймеры, совместимые
      с `poll`, и счётчик истечений через `timer_read`.
- [x] При повторном `http_get_ipv4` длина ответа сбрасывается в начале вызова;
      ранние ошибки не оставляют видимым предыдущий ответ, а при ошибке чтения
      сохраняются только байты текущего вызова. Loopback tests проверяют повторное
      использование буфера; см. `docs/http.md`.
- [x] Запись каждого float в `put_float` форматируется в ограниченном локальном
      буфере и отправляется одним `write_all`; байтовый формат, точка вывода и
      обработка ошибки сохранены. Regression tests покрывают края форматирования
      и ошибку записи (`/dev/full`); это не буферизует целиком `print(...)`.
- [x] [Лексические срезы](docs/slice-borrows.md): `[]T` или исключительный
      `[]mut T` из локального массива; дочерний `[]T` диапазона из `[]mut T`;
      возврат `[]T` от одного явно указанного
      параметра. Нет анализа последнего использования или raw-указателей.
- [x] Мономорфизация обобщённых функций и структур. `Buffer<T>` предоставляет
  растущую типизированную память с ручным освобождением.

## Match, типизированные ошибки и владение

- [x] [Составные `Option`/`Result`](docs/option-result-payloads.md): копируемые
      структуры и вложенные размеченные значения; передача, возврат, `match` и
      `?` по внутреннему ABI VOLT с сохранением порядка `defer`.
- [x] [Enum с данными](docs/enum-payloads.md): один скаляр на вариант и
      исчерпывающий `match`. ABI старых enum без данных не меняется.
- [x] [`module` и `pub`](docs/modules.md): квалифицированные имена, закрытые
      конструкторы и переходная совместимость `use`.
- [x] [`OwnedBuffer`](docs/owned-buffer.md): перенос целиком, диагностика после
      возможного переноса, автоматический `drop` после `defer`.
- [x] [`Result<OwnedBuffer, E>`](docs/owned-buffer.md): перенос в `Ok`, извлечение
      через `match` и `?`, освобождение живого `Ok` после `defer`.
- [x] [`fs.OwnedFd`](docs/owned-fd.md): реестр владеющих типов вместо жёсткой
      привязки к `OwnedBuffer`, `fs.open_owned`, автоматический `close(2)`
      ровно один раз после `defer`, `Result<fs.OwnedFd, E>` по той же схеме.
- [x] [`fs.read_all`](docs/owned-buffer.md): чтение целого файла в
      `Result<OwnedBuffer, fs.IoError>` с лимитом `max_bytes` (`EFBIG` сверх
      лимита, `EINVAL` при неположительном) — первый клиент переноса владения
      через `?` без ручного освобождения буфера.
- [x] [`TextView`](docs/text-view.md): сохранённая длина, доступ к байту и
      поддиапазон за O(1); явный переход к C-строке.
- [x] [`T: Eq`](docs/language.md#ограничение-t-eq): проверка при вызове,
      мономорфизация без динамической диспетчеризации.

## Реализованные проверенные расширения

- [x] Стековые аргументы для фиксированных сигнатур VOLT, `extern`/`native`
      и скалярных C-колбэков. GP и SSE выделяются независимо. Тесты сверяют
      смешанную сигнатуру с C в обе стороны и вызывают реальные `qsort`,
      `modf` и `modff`. Вариативные вызовы не входят.
- [x] [`extern struct`](docs/language.md#структуры-по-значению-в-c-abi): прямые
      `extern fn` с естественным layout и скалярными полями до 16 байт. Проверены
      класс регистров, стек, размер, выравнивание и смещения полей на C-библиотеке.
- [x] Типизированный непрямой вызов локального `fnptr` в `unsafe`, включая
      смешанные аргументы на стеке и скалярные результаты C.
- [x] Явное подключение C-библиотек через [`volt.mod`](docs/volt-mod.md) без
      загрузки пакетов и скриптов сборки.
- [x] [`use thread`](docs/thread.md): `mutex_try_lock` и условные переменные с
      монотонными дедлайнами. [`use channel`](docs/channel.md): передача `i64`
      по значению с ожиданием и вариантами `try`; создание потоков остаётся `unsafe`.
- [x] [`use arena`](docs/arena.md): линейный аллокатор с одной областью для
      временных объектов, выравниванием и групповым освобождением в `unsafe`.
- [x] [`BorrowBuffer<T>`](docs/buffer-borrow-proposal.md): лексические чтения
      и проверка всех копий владельца при записи, росте и освобождении.
- [x] Диагностика показывает ограниченный фрагмент загруженного исходника.
      `-g` добавляет DWARF 4 для строк объявления функций, не для отдельных
      операторов. Базовый фаззинг с фиксированным seed отдельно проверяет
      парсер и генерацию ELF.
- [x] `use fs` создаёт каталоги, переименовывает без перезаписи и удаляет файлы
      и пустые каталоги. `use event` предоставляет неблокирующие операции
      над потоковыми сокетами и пару локальных сокетов. `use thread` добавляет
      pthread и мьютексы для Linux x86-64 с glibc ≥ 2.34; владение ручное.
- [x] Опциональный модуль `use sdl` для одного SDL2 окна и software renderer:
      явные `sdl_init`/`sdl_quit`, создание/уничтожение окна и renderer,
      цвет, очистка, заливка прямоугольника и present одного кадра. Функции
      unsafe, handles — сырые opaque pointers с ручным владением; порядок очистки
      renderer → window → `sdl_quit`. Проверки размеров/цветов/координат защищают
      сужение к SDL integer types. Импорт добавляет `link "-lSDL2"` и требует
      SDL2 development files при сборке и SDL2 shared library при запуске.
       Проверка `tests/sdl_integration.py` под `SDL_VIDEODRIVER=dummy` подтверждает
       сборку, успешные вызовы и lifecycle, но не видимые пиксели.
- [x] Минимальный `use window` convenience API поверх SDL2: `Window`, lifecycle,
      очистка, заливка прямоугольника, present и polling SDL_QUIT/window-close.
        `window_create` возвращает `Window` напрямую через sret и использует
         нулевой sentinel при ошибке; этот API ещё не переведён на `Result`.
- [x] README quick-start с Hello World, командами запуска из корня `vega/` и
      ожидаемым выводом; пример также находится в `apps/hello.volt`.
      Подтверждены `./volt apps/hello.volt --run` и сборка с `-o` с
      ожидаемым выводом `Hello, VOLT!` и кодом 0.

SDL2 binding поддержан только текущим reference target Linux x86-64/System V.
Это не общий event loop: API событий и ввода, pixel readback/assertions,
textures/loaders, OpenGL/Vulkan, audio и cross-platform ABI guarantee отсутствуют.
CLI принимает `--target linux-x86_64` (по умолчанию используется эта же цель);
другие цели не реализованы. Windows и D3D11 пока не поддерживаются.

## Приоритетные следующие инкременты (предложения, не реализованы)

1. **Готовность и отмена I/O.** Добавить один ожидающий цикл с дедлайном и
   явной отменой через дескриптор пробуждения; проверить частичные передачи,
   гонку отмены с завершением и закрытие. Синхронные файлы и `async/await`
   языка остаются отдельными этапами.
2. **Безопасные convenience API для HTTP-ответа.** Аудит предложил после
   исправленного reset длины рассмотреть проверку/разбор status и headers или
   bounded slices; транспорт сейчас возвращает только сырой ответ и не должен
   трактоваться как полноценный HTTP stack. Сперва определить безопасную модель
   длины/времени жизни; сохранять текущие лимиты и явное `unsafe` владение.
3. **Расширить бенчмарки до измеряемых оптимизаций.** ✅ Добавлены фиксированные
   workloads для безопасной индексации строк, cached-length + unsafe pointer
   обхода и вывода; runner проверяет результат, прогревает программу и сообщает
   median/range без порогов производительности. Замеры не являются гарантиями и
   сравнимы только при одинаковом окружении. В контрольном запуске на текущей
   машине 200k обращений заняли 2.628 ms безопасным индексом и 1.054 ms для
   cached-length + unsafe pointer; эти цифры — иллюстрация, не гарантия.
   [`benchmarks/compiler_run.py`](benchmarks/compiler_run.py) отдельно измеряет
   сборку браузера и компилятора. Ускоренный поиск строковых ключей дал медианы
   2.582 → 2.140 с и 3.048 → 2.457 с соответственно (четыре чередующихся прогона
   на одном CPU, одна версия исходников с оптимизацией и без неё).
   Выходные ELF совпали побайтно.
4. **Измерить стоимость безопасной индексации строк.** Каждый индекс сейчас
   пересчитывает `strlen`, поэтому проход по строке длины L с N обращениями
   имеет стоимость O(N·L). После расширения benchmark сравнить безопасный индекс
   с cached `str_len` и unsafe pointer-индексацией; документировать, что
   pointer-путь обходит проверки, а unsafe alias может изменить/перезаписать NUL
   и сделать кэш длины недостоверным. Для нового кода доступен `TextView` без
   изменения семантики или ABI `string`.
5. **Добавить рецепт владения `ByteBuffer` и выровнять команды примеров.** ✅
   `apps/bytebuffer.volt` демонстрирует init → проверку статуса → потребление
   байтов → free внутри явной границы `unsafe`; команды `demo.volt` и `sort.volt`
   используют основной CLI `./volt`.

## Дальнейшие направления (не обещания релиза)

Следующий шаг для FFI — заменить ручные переходники в `use cuda` на проверенные
типизированные вызовы `fnptr`. Открыты расширение C-layout, экспорт функций
и вариативный ABI. Для памяти остаются более общая проверка времени жизни,
пользовательские некопируемые типы и частичный перенос. Для `-g` — привязать адреса
к операторам, затем добавить локальные переменные и типы. За пределами
smoke-фаззинга — расширить корпус и сверять вывод сгенерированных программ
с независимой моделью для арифметики и управления потоком.

Traits, атомики, проверка передачи общих объектов между потоками, пакетные инструменты, language server,
многоплатформенность и переносимый runtime остаются открытыми направлениями.
За пределами реализованного SDL2 software-rendering API дальнейшие графические
возможности не обещаны:
OpenGL/Vulkan, audio и загрузчики текстур/моделей не реализованы.

## Развитие браузерного движка

- [x] Типизированные буферы для DOM и раскладки. Локальные документы и HTTP(S)
  поддерживают HTML до 2 МиБ, с отдельными пределами для узлов и фрагментов.
- [x] Внешние стили с того же origin, PNG/JPEG/WebP, пропорциональные шрифты и
  базовые Flexbox, Grid, таблицы и медиазапросы.
- [x] Типизированные колбэки C для чтения PNG и фонового загрузчика SDL.
- [ ] Полный алгоритм восстановления HTML5, внешние шрифты и дальнейшее
  расширение моделей раскладки CSS.
- [x] Экспериментальные встроенные сценарии JavaScript, текстовый DOM и клики
  с отдельным процессом на страницу.
- [ ] Расширение DOM API, ресурсы для сценариев и аудит изоляции недоверенных страниц.
- [ ] Подключить внутренний fMP4-проигрыватель к ограниченному веб-API
  MediaSource. Сначала проверить append, завершение и отмену на локальном
  `<video>`, не ослабляя same-origin/CSP. Затем оценить официальный YouTube
  embed: ему также нужны жизненный цикл iframe и более полный DOM/сетевой API.

Текущая реализация рассчитана на Linux x86-64/System V ABI. Владение памятью
в `Buffer<T>` ручное. Оконная загрузка выполняется в фоне.
[Документация движка](docs/html-engine.md).
